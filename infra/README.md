# InsightHub Day 3 Terraform

This directory contains the Day 3 IaC artifact for InsightHub.

## What It Creates

- Kubernetes namespace and IRSA ServiceAccount for InsightHub.
- RDS PostgreSQL 16 for pgvector-backed document storage.
- ElastiCache Redis 7 for async ingestion queueing.
- AWS Secrets Manager secrets for database and Redis credentials.
- KMS encryption for managed services and secrets.
- Security groups that only allow EKS node/pod traffic to RDS and Redis.

The module assumes an existing EKS cluster and VPC. It does not create a new
cluster, because Day 3 focuses on application infrastructure and the CI/CD
path.

## Backend

`backend.tf` is intentionally a production template. Before a real
`terraform init`, replace:

- `REPLACE_WITH_INSIGHTHUB_TFSTATE_BUCKET`
- `REPLACE_WITH_INSIGHTHUB_TFLOCK_TABLE`

For CI validation without a real backend, the workflow runs:

```bash
terraform init -backend=false
```

## Local Review Flow

```bash
cp terraform.tfvars.example terraform.tfvars
terraform fmt -recursive
tflint --recursive
checkov -d . --soft-fail-on LOW,MEDIUM
terraform init -backend=false
terraform validate
terraform plan
```

Do not run `terraform apply` until you have reviewed the plan and confirmed the
estimated AWS cost.

## Security Notes

- Credentials are generated by Terraform and stored in AWS Secrets Manager.
- RDS and Redis are private-only.
- RDS storage, Redis storage, logs, and Secrets Manager values use KMS.
- Runtime AWS access uses IRSA, not IAM users.
- `terraform.tfstate` can contain sensitive generated values and must stay out
  of Git.
